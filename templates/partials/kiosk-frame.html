{# Frame bridge — what a kiosk page says to the shell that is rendering it. Include once, in , on every kiosk destination: {% include 'partials/kiosk-frame.html' %} welcome.html is now the only document the terminal loads; the six destinations render inside its content frame, driven by the carousel. That frame boundary blocks events, so the shell cannot see a visitor panning the map or turning a page — this partial is how the page tells it. Inline rather than a compiled entry, for the same reason the back bar's handler used to be: this is included by six templates that agree on no shared JS bundle at all (campus-map and org-board extend base.html and load no kiosk JS whatsoever). A compiled entry would have to be added to each of them anyway, and would be subject to the very cache it participates in. Two things are published, both guarded so a double include is harmless (About LSPU includes the back bar twice, and had the same guard): window.__kioskFrame.embedded — are we inside the shell's content frame? window.__kioskFrame.post(t) — send the shell a message `embedded` reads window.name rather than `window.top !== window.self`, because the shell frames a kiosk page in TWO ways that want opposite behaviour, and those are identical to a top/self comparison: - the content frame, named "kiosk-content" — the page the visitor is actually using; - the attract overlay, unnamed — /kiosk/embed/latest-news looping decoratively behind pointer-events:none, where there is no visitor to report activity for and kiosk-news.js already suppresses its own timer. welcome.html renders name="kiosk-content" as an attribute, so it is readable here at parse time rather than arriving later as a message. #}
